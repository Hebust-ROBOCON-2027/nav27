## 1. 物理层

| 项 | 值 |
|---|---|
| 链路 | **USB CDC 虚拟串口**（STM32 USB 设备，Linux 下节点 `/dev/ttyACM*`） |
| 波特率 | `115200`（CDC 下内核忽略该值，仅作兼容保留；物理 UART 时双方须一致） |
| 数据格式 | 8N1（8 数据位，无校验，1 停止位） |
| 字节序 | 小端（Little-Endian） |
| 校验 | CRC-16/Modbus |

### 关于 USB CDC 与 UART

上位机通过内核 `cdc_acm` 驱动把 STM32 的 USB CDC 设备映射成 `/dev/ttyACM0`，
代码用标准 termios 读写该节点——**这就是 USB CDC 通信**，
只是走内核提供的 tty 接口，不需要应用层直接操作 USB 端点。

两种接法代码都支持，只改 `port_name` 参数：

| 下位机接法 | Linux 节点 | `port_name` |
|---|---|---|
| STM32 USB 口直连（CDC） | `/dev/ttyACM0` | `/dev/ttyACM0`（默认） |
| UART TTL 经 USB 转串口芯片（CH340 / CP210x / FTDI） | `/dev/ttyUSB0` | `/dev/ttyUSB0` |

波特率只在第二种（物理 UART）下有意义；CDC 走 USB 带宽，设成多少都不影响实际速率。

权限（打开失败时先查这个）：

```bash
sudo usermod -aG dialout $USER    # 注销重登生效
# 或临时：sudo chmod 666 /dev/ttyACM0
```

## 2. 帧格式

```
┌───────┬────────┬──────┬─────────┬─────────┐
│ 帧头  │ 命令字 │ 长度 │  数据   │ CRC校验 │
│ AA 55 │ 1 byte │1 byte│ N bytes │ 2 bytes │
└───────┴────────┴──────┴─────────┴─────────┘
```

| 字段 | 长度 | 说明 |
|---|---|---|
| 帧头 | 2 | 固定 `0xAA 0x55` |
| 命令字 | 1 | 见命令表 |
| 长度 | 1 | 数据区字节数，**不含**帧头/命令字/长度/CRC |
| 数据 | N | 见各命令定义 |
| CRC | 2 | CRC-16/Modbus，**低字节在前** |

- **帧总长 = `LEN + 6`**
- CRC 之后即帧结束，没有单独的帧尾字节

### 帧头为什么选 `0xAA 0x55`

单字节帧头误判概率 1/256 太高——数据区里碰巧出现同一个字节是常有的事。
两字节降到 1/65536，再叠一层 CRC16，整体误判概率约 **1/2^32**。

```
0xAA = 10101010
0x55 = 01010101
```

两者是互补的交替位模式。本协议数据区全是 float 且值域很小
（速度 `|v| ≤ 3.0`、角速度 `|ω| ≤ 5.0`、转向角 `|θ| ≤ π`），
小端存放时最高字节是「符号+指数」，集中在 `0x3F / 0x40 / 0xBF / 0xC0` 附近，
其余是尾数字节，不会出现这种规则交替模式。

实测典型值（小端）：`1.0 → 00 00 80 3F`、`2.0 → 00 00 00 40`，均不含 `AA` / `55`。

## 3. CRC-16/Modbus

参数：多项式 `0xA001`（反射形式），初值 `0xFFFF`，无最终异或。

**覆盖范围（联调前必须双方确认一致）**：默认**不含帧头**

```
参与 CRC 的字节 = 命令字 + 长度 + 数据
```

电控若要把帧头也算进去，上位机改 `protocol.hpp` 里 `CRC_START_OFFSET = 0` 即可。
**两边不一致则所有帧校验失败**（上位机表现为日志里 `废帧 CRC` 持续上涨）。

```c
uint16_t crc16_modbus(const uint8_t* data, size_t length) {
    uint16_t crc = 0xFFFF;
    for (size_t i = 0; i < length; i++) {
        crc ^= data[i];
        for (int j = 0; j < 8; j++) {
            if (crc & 0x0001) crc = (crc >> 1) ^ 0xA001;
            else              crc >>= 1;
        }
    }
    return crc;
}
// 发送：crc_lo = crc & 0xFF;  crc_hi = (crc >> 8) & 0xFF;  低字节先发
```

## 4. 命令表

| 命令字 | 方向 | 含义 | 数据区 | 长度 |
|---|---|---|---|---|
| `0x01` | 上位机→电控 | 车体速度指令 | `vx` + `vy` + `wz` | 12 B |
| `0x02` | 上位机→电控 | 急停 | 无 | 0 B |
| `0x10` | 电控→上位机 | 舵轮状态反馈 | 4×角度 + 4×轮速 | 32 B |

其余命令字空间预留。

---

## 5. `0x01` 速度指令（上位机→电控）

数据区 12 字节，**车体坐标系速度**：

| 偏移 | 长度 | 类型 | 字段 | 范围 |
|---|---|---|---|---|
| 0 | 4 | float | `vx` | [-3.0, 3.0] m/s |
| 4 | 4 | float | `vy` | [-3.0, 3.0] m/s |
| 8 | 4 | float | `wz` | [-5.0, 5.0] rad/s |

**舵轮逆运动学由电控固件完成**：上位机只发车体速度，由固件解算成
4 个舵轮的「转向角 + 转速」。换底盘不用改协议。

### 坐标系（必须遵守）

```
            vx +（车头方向为正）
                 ↑
                 |
    vy +  <------+------ （车体左侧为正）

    wz + ：俯视逆时针为正（ROS REP-103，Z 轴朝上）
```

上位机保证：`|vx|≤3.0`、`|vy|≤3.0`、`hypot(vx,vy)≤3.0`、`|wz|≤5.0`。
合速度超限按模长等比缩放，**方向不变**。

协议不做任何取负或换轴。装机后方向不对，改上位机 ROS 参数
`invert_vx / invert_vy / invert_wz / swap_xy`，**不要改固件**。

---

## 6. `0x02` 急停（上位机→电控）

无数据区，`LEN = 0`。收到立即刹车并保持，直到收到新的速度指令。

---

## 7. `0x10` 舵轮状态反馈（电控→上位机）

数据区 **32 字节** = 4 个转向角 + 4 个轮速：

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 16 | `angle[0..3]` | 4 个舵轮当前转向角，**rad**，范围 [-π, π] |
| 16 | 16 | `speed[0..3]` | 4 个舵轮当前轮速，**m/s** |

- 角度：`0` = 轮子与车头同向，逆时针为正
- 轮序：左前 / 右前 / 左后 / 右后
- 建议周期 50 Hz

**为什么舵轮必须回传转向角**：只给轮速算不出里程——
转向角偏差和侧向打滑都不可观，轮速积分误差会迅速发散。

上位机发布到 `/AT_R2/steer_state`（`Float32MultiArray`，前 4 个角度，后 4 个轮速）。

## 8. 示例帧（用来对 CRC 实现）

CRC 覆盖 = 命令字 + 长度 + 数据（不含帧头）。

| 场景 | 帧长 | 完整帧（十六进制） |
|---|---|---|
| 速度 `vx=1.0, vy=0.0, wz=0.5` | 18 | `AA 55 01 0C 00 00 80 3F 00 00 00 00 00 00 00 3F E8 05` |
| 急停 | 6 | `AA 55 02 00 00 D0` |
| 舵轮状态 角度全 0、轮速全 0.5 | 38 | `AA 55 10 20 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 3F 00 00 00 3F 00 00 00 3F 00 00 00 3F 92 79` |

电控先把这几串用串口工具发给上位机：上位机 `收` 计数在涨且 `废帧 CRC` 为 0，说明两边一致。

## 9. 通信时序与异常处理

| 情形 | 上位机行为 |
|---|---|
| 正常 | 50 Hz 连续下发速度帧，**不等 ACK、不重传** |
| cmd_vel 超过 200 ms 没更新 | 改发零速，重复 10 次后停发 |
| `estop_on_timeout:=true` | 超时改发一次 `0x02` 急停帧 |
| 串口读写错误 / 设备拔出 | 关闭并重连，间隔 500 ms |

**电控侧务必加看门狗：超过 1 s 收不到速度帧就刹车**，防止上位机卡死导致飞车。

舵轮额外注意：转向角换向有机械极限，转向角速度限制由固件处理，
上位机不感知单轮状态。

## 10. 电控解析要求

1. 串口是字节流，一次接收可能是半帧或一帧半，**必须环形缓冲攒字节**
2. 找帧头 `0xAA 0x55` → 读 `LEN` → 凑够 `LEN + 6` 字节 → CRC 校验
3. 校验失败或 `LEN` 非法时，**只丢弃 1 字节**重新找帧头，不要大段丢弃（会误杀真帧）
4. 三个条件全过才取数据，不做部分解析
